# تنظیمات

**زبان:** [English](../en/Configuration.md) · فارسی

نام پیش‌فرض فایل `pulsecheck.yml` است (با `-c` عوض می‌شود). هر `${NAME}` داخل یک مقدار با متغیر محیطی `NAME` جایگزین می‌شود. نبودن متغیر خطا است، پس رمزها و توکن‌ها را داخل فایل ننویسید.

```yaml
state_file: pulsecheck.db
shoutrrr_bin: shoutrrr
notify:
  urls: ["telegram://${TG_TOKEN}@telegram?chats=${TG_CHAT}"]
  events: [down, up, degraded]
defaults: {timeout: 10, down_after: 2, interval: 5, slow_ms: 3000}
maintenance:
  - {name: weekly, start: "SUN 02:00", duration: 60, sites: [api]}
sites:
  - {name: web, url: https://example.com}
```

## سطح اول
| کلید | پیش‌فرض | توضیح |
|---|---|---|
| `state_file` | `pulsecheck.db` | فایل SQLite برای وضعیت فعلی و تاریخچه بررسی‌ها (۴۰۰ روز نگهداری می‌شود) |
| `shoutrrr_bin` | `auto` | `auto` (image داکر اگر Docker کار کند، وگرنه فایل اجرایی `shoutrrr`)، `docker` یا مسیر یک فایل اجرایی |
| `shoutrrr_image` | `nickfedor/shoutrrr:0.21.2` | image داکر برای حالت `auto` و `docker` |
| `notify` | ندارد | مقصدهای سراسری هشدار (پایین‌تر توضیح داده شده) |
| `defaults` | `{}` | هر کلید سایت؛ به همه سایت‌ها اضافه می‌شود (مقدار خود سایت اولویت دارد) |
| `messages` | پیش‌فرض داخلی | متن هشدارها بر اساس کلید، بخش «پیام‌ها» پایین همین صفحه |
| `maintenance` | `[]` | بازه‌هایی که هشدارها ارسال نمی‌شوند |
| `sites` | الزامی | فهرست بررسی‌ها؛ `name` باید یکتا باشد |

## کلیدهای هر سایت
| کلید | پیش‌فرض | مناسب برای | توضیح |
|---|---|---|---|
| `name` | الزامی | همه | نام یکتا برای هشدارها و گزارش |
| `type` | `http` | همه | `http` یا `tcp` یا `ping` |
| `url` | – | http | آدرس کامل (الزامی) |
| `host` | – | tcp، ping | نام میزبان یا IP (الزامی) |
| `port` | – | tcp | پورت (الزامی) |
| `method` | `GET` | http | متد HTTP |
| `headers` | `{}` | http | هدرهای درخواست |
| `body` | – | http | بدنه درخواست (رشته) |
| `expected_status` | هر 2xx | http | فهرستی مثل `[200, 301]` |
| `max_redirects` | `5` | http | حداکثر تعداد ریدایرکت قابل دنبال‌کردن |
| `max_response_ms` | خاموش | همه | کندتر از این مقدار یعنی **شکست** |
| `slow_ms` | خاموش | همه | کندتر از این (ولی موفق) یعنی **degraded** |
| `timeout` | `10` | همه | ثانیه |
| `down_after` | `2` | همه | تعداد شکست پشت‌سرهم قبل از down شدن |
| `interval` | `5` | همه | فاصله بررسی‌ها به دقیقه (پایین‌تر ببینید) |
| `notify` | سراسری | همه | جایگزین `notify` سراسری برای همین سایت |
| `messages` | سراسری | همه | جایگزین متن پیام‌ها فقط برای همین سایت |

## وضعیت و هشدار
- بررسی موفق یعنی `up`؛ اگر حداقل `slow_ms` طول کشیده باشد `degraded`.
- بررسی ناموفق فقط بعد از `down_after` شکست پشت‌سرهم سایت را `down` می‌کند. قطعی‌های کوتاه هشدار نمی‌سازند.
- هشدار **فقط هنگام تغییر وضعیت** ارسال می‌شود: `down`، `degraded` یا `up` (بازگشت؛ پیام می‌گوید چند دقیقه مشکل بوده است).
- `events` مشخص می‌کند کدام‌یک از `down`، `up`، `degraded` ارسال شود. `notify` سطح سایت، `notify` سراسری را کامل جایگزین می‌کند (با `events` آن).
- خطای ارسال هشدار (نبودن برنامه، آدرس اشتباه) در stderr چاپ می‌شود و اجرا را متوقف نمی‌کند.

## بازه بررسی (interval)
اینکه pulsecheck هر چند دقیقه اجرا شود را زمان‌بند شما تعیین می‌کند؛ `interval` فقط سایت‌هایی را که تازه بررسی شده‌اند رد می‌کند. مثلاً اجرای هر ۵ دقیقه، و برای یک بررسی سنگین `interval: 60` تا ساعتی یک‌بار اجرا شود. یک دقیقه تلورانس برای تأخیر زمان‌بند در نظر گرفته می‌شود، پس `interval: 5` با زمان‌بندی ۵ دقیقه‌ای در هر اجرا بررسی می‌کند.

## بازه نگهداری (maintenance)
زمان‌ها **UTC** هستند. `start` به شکل `"HH:MM"` (هر روز) یا `"DAY HH:MM"` با `MON TUE WED THU FRI SAT SUN` است. `duration` به دقیقه است و می‌تواند از نیمه‌شب عبور کند. خالی‌بودن `sites` یعنی همه سایت‌ها. بررسی‌ها انجام و ثبت می‌شوند، اما هشدارهای این بازه حذف می‌شوند و بعداً ارسال نمی‌شوند.

## پیام‌ها
هر متن هشدار یک کلید دارد. کد فقط از همین کلیدها استفاده می‌کند و هر کدام را می‌توانید زیر `messages:` تغییر دهید (سراسری یا داخل یک سایت). کلیدهایی که ننویسید متن داخلی خود را نگه می‌دارند.

| کلید | زمان ارسال | متن داخلی |
|---|---|---|
| `down` | سایت down شد | `🔴 {site} is DOWN: {error}` |
| `degraded` | سایت بالاست ولی کند است | `🟡 {site} is slow ({ms}ms)` |
| `up` | سایت برگشت | `🟢 {site} is UP ({ms}ms) after {minutes}m` |
| `test` | `pulsecheck test-notify` | `pulsecheck test notification` |

جانگهدارها: `{site}` نام سایت، `{event}` (`down`/`degraded`/`up`)، `{error}` دلیل شکست (در حالت موفق خالی)، `{ms}` زمان پاسخ، `{minutes}` دقیقه‌های گذشته از آخرین تغییر وضعیت، `{status}` کد وضعیت HTTP (برای tcp/ping خالی). برای آکولاد واقعی `{{` و `}}` بنویسید. کلید یا جانگهدار ناشناخته در `validate` رد می‌شود. اولویت: `messages` سایت، بعد `messages` سراسری، بعد متن داخلی.

```yaml
messages:
  down: "ALERT {site} unreachable ({error})"
  up: "{site} recovered after {minutes} min"
sites:
  - name: payments
    url: https://pay.example.com
    messages: {down: "💳 payments DOWN, page on-call"}
```

## گزارش
`pulsecheck report` برای روز / هفته / ماه / سال این موارد را نشان می‌دهد: درصد آپتایم، میانگین و p95 زمان پاسخ بررسی‌های موفق، و تعداد بررسی‌ها. `--json` همین داده را برای اسکریپت‌ها چاپ می‌کند.
